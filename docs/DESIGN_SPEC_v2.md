## 1. 원칙 여섯 가지

1. **선에 맞춘다.** 12칸 그리드(간격 24, 세로 32). 제목·숫자·카드·표·버튼이 같은 세로선에서 시작하고, 머리 아래 **잉크 룰 하나**에서 왼쪽 8칸과 오른쪽 4칸이 같이 출발한다. 카드는 테두리·그림자 없이 **사진 자체가 카드**. 같은 정보를 화면에 두 번 보여 주지 않는다.
2. **사진 + 상태 한 문장 (v2.2).** 진행 중인 모든 것(요청 항목·제안·샘플·발주)은 3:4 실물컷 카드(데스크톱 3칸=4열, 모바일 2열). 사진 아래 **이름(+수량 또는 가격, muted)** 과 **지금 상태 한 문장**("샘플 받음 · 11월 18일까지 돌려보내기", "중국에서 출고 준비 중 · 11월 9일")뿐. 5단계 트랙·상태 점·코드·체크박스는 쓰지 않는다. 사진 위 라벨은 **'할 일'(금색 점)과 '새 제안'** 둘만. 행동이 있으면 카드 아래 버튼("회수 선택", "관심 · 샘플에 담기"). 사진이 없는 요청 항목은 빗금 면.
3. **숫자는 가볍고 크게.** 핵심 금액·수량·건수는 SUIT 300 weight 40px(모바일 34). 보조 숫자는 13px. 돈 합계 위에만 금색 룰.
4. **금박은 한 화면에 세 번까지.** 모노그램 테두리, "내 차례" 왼쪽 2px 룰(+상태 점), 청구 합계 룰. 그 밖에는 쓰지 않는다. 네이비는 링크·포커스·버튼 hover.
5. **사람 말로, 한 문장 (v2.2).** 할 일 = "무엇을 언제까지" 한 문장 + 버튼("에코퍼 크롭 카라 자켓 샘플을 돌려보내 주세요 / 11월 18일까지"). 상태 = 지금 상태 + 다음 행동. 상세 화면 제목 아래는 **지금 상태 한 덩어리**(썸네일 + "위아더가 확정하고 있어요" + 한 문장)로 핸드오프 카드를 대신한다. 버튼은 결과까지 말한다("관심 · 샘플에 담기", "이메일로 로그인"). 내부 용어(핸드오프·차례·리오더 뱃지·#코드·눈썹 대문자)는 브랜드 화면에 내지 않는다. 금색은 **H1 아래 28px 룰 하나**와 '할 일' 점에만.
6. **메뉴는 넷.** 홈(대시보드) · 진행 · 청구 · 설정. 요청·제안·샘플·발주는 메뉴가 아니라 진행 화면의 **단계이자 필터 칩**. 상세 화면과 URL(`/requests/[id]`, `/offers/[id]`, `/samples/[id]`, `/orders/[id]`, `/exports`)은 그대로 두고 들어가는 길만 바뀐다. 모바일은 같은 카드가 2열, 메뉴 넷은 가로 스크롤 없이 들어간다.

## 3. 레이아웃 — 12칸 그리드

- `.g12 { grid-template-columns: repeat(12, minmax(0,1fr)); gap: 32px 24px }` 최대 폭 1200. **모든 페이지 본문은 이 그리드 하나 안에 놓는다**: 머리(8+4) → 잉크 룰(12) → 본문(8+4 또는 3×4 카드) → 섹션 머리(12).
- **상세 화면의 머리(v2.6)**: 눈썹·H1(8칸) → **12칸 잉크 룰 한 줄** → 왼쪽 8(상태 블록·선택지·표) / 오른쪽 4(청구표·레일). 룰 바로 아래 블록은 **윗 룰·윗 여백 없이 같은 y(룰 + 32)에서 시작** — 왼쪽 `.nowblock`·`.style-card` 첫 것은 `border-top: 0; margin-top: 0; padding-top: 0`, 오른쪽 `.invoice`·`.rail`은 `border-top: 0; padding-top: 0`. 오른쪽 4칸이 자기 윗 룰을 따로 갖지 않는다(지금 dev처럼 왼쪽 H1 룰과 오른쪽 룰이 다른 y에 두 줄로 보이는 것이 "좌우가 안 맞는" 원인).
- **반응형 4단(v2.6)** — 12칸·간격 24는 어디서나 같고 `span`과 거터만 바뀐다. 경계는 `max-width: 1023.98px / 767.98px / 639.98px`(= 1024·768·640 자체는 큰 쪽).
  - **XL ≥ 1024**: 거터 40(1024~1279는 32), 카드 3칸(4/행), 상세 8/4, 머리 8+4.
  - **M 768–1023**: 거터 32, 카드 **4칸(3/행)**, 상세 8/4 → **12로 쌓기**(오른쪽 4칸은 왼쪽 본문 뒤, 윗 잉크 룰 + 28), 머리 버튼은 H1 아래 **오른쪽 정렬**, `.two.half`(지금까지|위아더에게)는 그대로 둘.
  - **S 640–767**: 거터 24, display 34/40 · h1 24/32, `.two.half` → 한 칸, 필터 칩 한 줄 + 가로 스크롤(`white-space: nowrap`).
  - **XS < 640**: 거터 20, 카드 6칸(2/행), `.g12` 간격 28/16, 헤더는 **모노그램 + 브랜드명 + 알림**(워드마크·메뉴·이름 숨김) + 44px `.subnav`, 머리 버튼은 전폭(`.tr .btn { flex: 1 }`, `.btn.lg { width: 100% }`), 썸네일 56 + 16, 소그리드(`.kv` `.grid3` `.src`)는 한 칸씩 쌓기, 선택지 라디오 열 24 + 12, 타임라인 `auto 1fr` 한 줄, 카드 상태 문장 2줄까지.
  - 금지: 960 같은 중간 경계, `max-width: 960px`처럼 경계값을 작은 쪽에 포함시키는 쿼리, 카드를 2/행으로 키우는 M 구간(사진이 450px로 커진다).
- **타임라인(v2.6)**: 날짜는 `li.day`(12/16 muted) 한 줄로 먼저, 그 아래 `li`는 시각 1칸(71) + 24 → 내용 둘째 선. 접수 완료의 큰 타임라인만 166 + 24.
- **정렬 완료 조건(v2.3)**: 블록의 왼쪽 모서리는 그리드 선, 오른쪽 모서리는 칸 오른쪽 끝(다음 선 − 24) — 둘 다 아닌 블록 없음(±2px). 표는 `table-layout: fixed` + `<colgroup>` 12분의 n, 숫자 열 우정렬 `padding-right: 24px`, 상태 열 `nowrap + ellipsis`. 오른쪽 4칸의 윗선 = 왼쪽 메타 줄 y. 섹션 머리는 아래 1px 룰, 바로 아래 블록은 윗 룰 없음. 검사: `docs/design/grid-audit.js`(콘솔) `offCount: 0`.
- **정렬 완료 조건 v2.4 — 블록 "안"의 선**(5차 측정, NEXT §0-h): ① 머리 행은 H1과 오른쪽 버튼·링크의 **아래 끝이 같은 y**(둘 다 `align-self: end`, 금색 룰은 절대 위치) ② 썸네일 폭 = **1칸(71) + 24** → 옆 글은 둘째 선 ③ 8칸 안 소그리드(`.kv` `.grid3` `.src`)는 `repeat(8, …) gap 24` + `span`(3·3·2 / 4·4 / 3·2·3) ④ 타임라인은 점·세로선 없이 날짜 줄(`li.day`) + 시각 1칸(71) + 24 → 내용 둘째 선 ⑤ 선택지는 라디오 열 47 + 24 → 글 둘째 선, 안쪽 입력 261(3칸) ⑥ 버튼 `min-width 166`(2칸), 나란히면 간격 24 ⑦ 사면 박스(요청 작성 스타일 카드 · 레일 · 청구표)는 **윗 룰만** — 내용이 선에서 시작 ⑧ 표 colgroup = n × (칸 + 24) / 폭(12분의 n이 아님) ⑨ 세로 리듬은 row-gap 32 · 섹션 56 하나, 임의 `mt-*`·음수 마진 금지 ⑩ `.figure` 값은 한 줄(긴 값 `.v.sm` 28px) → 도움말 줄 y 동일. 검사: `docs/design/line-audit.js` `badCount 0 · offCount 0 · doubles 0 · head.rightBottoms = h1Bottom`.
- 상단 바 64(모바일 56), 본문 상단 여백 48(모바일 28). 섹션 사이 56, 블록 사이 32(그리드 세로 간격).
- 상세 화면 = 왼쪽 8칸(또는 6+6) / 오른쪽 4칸 청구표(sticky). 제안 상세는 6칸 큰 사진(+썸네일 5) / 6칸 가격·스펙·반응.

## 6. 문구 규칙 (ko.json 전체 적용)

1. 제목 = 정보(상품명·수량·금액). 날짜는 눈썹/메타로.
2. 설명은 0~1문장. 두 문장째는 버튼이나 다음 화면이 말한다.
3. 인사말·화면 설명·UI 지시("~를 참고하세요", "~순서로 모았어요") 금지.
4. 주어 생략. "위아더가 ~하고 있어요" → "~ 중" 또는 "~해요". 위아더는 필요할 때만 명사로.
5. 버튼 = 동사 2~4자. 문장형 버튼·화살표 금지. 결과를 말한다("이메일로 로그인", "입금 신고").
6. 상태명 2~5자 명사. 핸드오프 제목은 "행동 + 대상(+금액)" 20자 이내.
7. 숫자는 글 앞에("₩221,390을 입금해 주세요", "샘플 1점을").
8. 괄호 설명 금지 — 필요하면 도움말 줄(12px muted)로.

전후 표(20개)는 프로토타입 "스타일 가이드" 아래. 구현 시 ko.json 전체를 이 규칙으로 훑는다(약 900키 중 브랜드 노출 문장형 키 ~150개 예상).

## 8. 글의 선 — 베이스라인·세로 리듬·디테일 (v2.5, 2026-11-05)

**원칙** 한 화면의 모든 글은 4px 세로 격자 위에 놓이고, 한 줄 안에서 글자가 위아래로 튀지 않는다. 숫자(SUIT)와 한글(Pretendard)이 섞여도 줄 상자 높이가 같다.

- **폰트 메트릭 통일**: 두 `@font-face` 모두 `ascent-override: 95%; descent-override: 24%; line-gap-override: 0%` (Pretendard 기준. SUIT 원래 99/26).
- **줄 높이 토큰(크기마다 하나)**: 12/16 · 13/20 · 14/20 · 16/24 · 20/28 · 28/36 · 40/48 · 56/64. 배수(1.6, 1.5…)·소수점 줄 높이 금지. `body` 14/20.
- **자간**: display −0.02em · 제목(h1·h2·todo·nowblock 제목) −0.01em · 본문·버튼 0 · 숫자 0 + `tabular-nums` · 눈썹 0.08em(관리자만).
- **간격 단위**: 라벨→값 8, 값→도움말 12, 사실 목록 줄 간격 8, 표 `th` 아래 12 · `td` 12/0(행 44), 타임라인 12(큰 것 20), 카드 이름→상태 4, 선택지 제목→설명 4, 입력 라벨→입력 8. 그 밖의 세로 여백은 §3의 32/56뿐.
- **₩ 기호**: 큰 숫자 앞 `small` = .5em, `line-height: 1`, `position: relative; top: −.72em`(기호 윗선 = 숫자 윗선), 오른쪽 .2em, ink-2. 줄 상자를 키우지 않는다.
- **상태 변화에 두께 변화 없음**: 입력 포커스 = 밑줄 색 잉크 + `box-shadow 0 1px 0` (2px 테두리 금지), 버튼 hover/active = 색만, `:focus-visible` = 1px signature 외곽선 offset 3.
- **버튼·칩·링크 치수**: `.btn` 44/안쪽 20/14/500 · `.sm` 36/12/13 · `.lg` 52/20/16, 최소 폭 2칸(§3). `.chip` 24/8/12. `.link` 13 + 1px line-strong 밑줄(hover 잉크, 글자 signature). 댓글 입력 44.
- **사진**: 3:4, well 배경, `inset 0 0 0 1px ink 6%` 안쪽 모서리(밝은 사진 경계). 빈 사진은 빗금.
- **섹션 머리**: h2 16/24 500 + 건수(SUIT muted, 왼쪽 8) · 아래 12 · line 1px. 머리 행(H1 + 버튼)은 밑선 하나(§3 ①).
- **검사**: `docs/design/type-audit.js`(콘솔) — 혼합 줄 상자 불일치 0, 줄 높이 목록이 토큰 8개 안.

## 1. 원칙 여섯 가지

1. **선에 맞춘다.** 12칸 그리드(간격 24, 세로 32). 제목·숫자·카드·표·버튼이 같은 세로선에서 시작하고, 머리 아래 **잉크 룰 하나**에서 왼쪽 8칸과 오른쪽 4칸이 같이 출발한다. 카드는 테두리·그림자 없이 **사진 자체가 카드**. 같은 정보를 화면에 두 번 보여 주지 않는다.
2. **사진 + 상태 한 문장 (v2.2).** 진행 중인 모든 것(요청 항목·제안·샘플·발주)은 3:4 실물컷 카드(데스크톱 3칸=4열, 모바일 2열). 사진 아래 **이름(+수량 또는 가격, muted)** 과 **지금 상태 한 문장**("샘플 받음 · 11월 18일까지 돌려보내기", "중국에서 출고 준비 중 · 11월 9일")뿐. 5단계 트랙·상태 점·코드·체크박스는 쓰지 않는다. 사진 위 라벨은 **'할 일'(금색 점)과 '새 제안'** 둘만. 행동이 있으면 카드 아래 버튼("회수 선택", "관심 · 샘플에 담기"). 사진이 없는 요청 항목은 빗금 면.
3. **숫자는 가볍고 크게.** 핵심 금액·수량·건수는 SUIT 300 weight 40px(모바일 34). 보조 숫자는 13px. 돈 합계 위에만 금색 룰.
4. **금박은 한 화면에 세 번까지.** 모노그램 테두리, "내 차례" 왼쪽 2px 룰(+상태 점), 청구 합계 룰. 그 밖에는 쓰지 않는다. 네이비는 링크·포커스·버튼 hover.
5. **사람 말로, 한 문장 (v2.2).** 할 일 = "무엇을 언제까지" 한 문장 + 버튼("에코퍼 크롭 카라 자켓 샘플을 돌려보내 주세요 / 11월 18일까지"). 상태 = 지금 상태 + 다음 행동. 상세 화면 제목 아래는 **지금 상태 한 덩어리**(썸네일 + "위아더가 확정하고 있어요" + 한 문장)로 핸드오프 카드를 대신한다. 버튼은 결과까지 말한다("관심 · 샘플에 담기", "이메일로 로그인"). 내부 용어(핸드오프·차례·리오더 뱃지·#코드·눈썹 대문자)는 브랜드 화면에 내지 않는다. 금색은 **H1 아래 28px 룰 하나**와 '할 일' 점에만.
6. **메뉴는 넷.** 홈(대시보드) · 진행 · 청구 · 설정. 요청·제안·샘플·발주는 메뉴가 아니라 진행 화면의 **단계이자 필터 칩**. 상세 화면과 URL(`/requests/[id]`, `/offers/[id]`, `/samples/[id]`, `/orders/[id]`, `/exports`)은 그대로 두고 들어가는 길만 바뀐다. 모바일은 같은 카드가 2열, 메뉴 넷은 가로 스크롤 없이 들어간다.

## 3. 레이아웃 — 12칸 그리드

- `.g12 { grid-template-columns: repeat(12, minmax(0,1fr)); gap: 32px 24px }` 최대 폭 1200, 거터 40(모바일 20). **모든 페이지 본문은 이 그리드 하나 안에 놓는다**: 머리(8+4) → 잉크 룰(12) → 본문(8+4 또는 3×4 카드) → 섹션 머리(12). 960 미만: 3칸→6칸, 4·6·8칸→12칸. 640 미만: 카드 6칸(2열).
- 상단 바 64(모바일 56), 본문 상단 여백 48(모바일 28). 섹션 사이 56, 블록 사이 32(그리드 세로 간격).
- 상세 화면 = 왼쪽 8칸(또는 6+6) / 오른쪽 4칸 청구표(sticky). 제안 상세는 6칸 큰 사진(+썸네일 5) / 6칸 가격·스펙·반응.
- 상단 바: 모노그램(28px 금색 1px 테두리, 시스템 세리프 "OS") + 워드마크 "OSLE SELECT"(SUIT 12px, 0.2em) + 브랜드명(16/500, 왼쪽 1px 룰). 메뉴 **홈 · 진행 · 청구 · 설정** 오른쪽 정렬, 활성은 **1px 밑줄**(바 하단과 겹침). 알림은 아이콘+건수, 이름 옆 역할은 12px muted. 640 미만: 바 아래 44px 가로 메뉴(`.subnav`).
- 관리자: 사이드바 232px `--ink`, 그룹 라벨 10px 0.18em 40%, 활성은 왼쪽 1px 금색 + 4% 흰 배경, 메뉴 오른쪽에 건수. 본문 패딩 40/48.
- 중국: 헤더 56px `--ink`, 가로 메뉴(건수 포함). 본문 최대 760. 외부 의존 0 유지.
- 로그인: 좌 `--ink` 면(모노그램·클레임 40px 300·3단계·바닥 문장) / 우 폼 360px. 960 미만 위아래.

## 5. 화면별 구조

**홈(대시보드) v2.2** — 개념 셋만. 8칸 "할 일 **n**"(40/300, n 금색, 아래 금색 룰) + 4칸 "상품 요청" 버튼 → 8칸 할 일 행(`.todo`, 기한 순) / 4칸 청구 예정(40, "확정 발주 1건 · 청구 보기") — 두 칸 모두 같은 1px 룰에서 시작 → "진행 중 n" 섹션 머리 → 사진 카드 3칸×4(최근 8). 눈썹·날짜·새 제안·항목 수 숫자 패널 삭제. 할 일 0이면 "할 일이 없어요"(28/400 ink-2) + 진행 중만.

**진행 v2.2**(신규, `/b/[slug]/progress`) — "진행 중인 상품 n" / 라인시트 PDF + 상품 요청 → 칩(전체 · 내가 할 일 n · 제안 도착 n · 샘플 n · 발주 n · 끝난 것) → **요청 묶음마다** 섹션 머리(요청명 · "11월 1일 요청 · 항목 2" / "제안은 11월 18일까지 유효해요") + 항목별 사진 카드 3칸(항목 1개 = 카드 1개, 단계가 올라가면 같은 카드의 문장이 바뀐다; 발주가 둘이면 발주 카드 둘). 제안 카드는 이름 옆 가격 + "관심 · 샘플에 담기"/"보류" 버튼; 관심을 누르면 문장이 "관심 표시함 · 샘플 요청서에 담김"으로 바뀌고 하단 담김 바가 뜬다. 체크박스·트랙 없음. 요청 20건 이상이면 묶음 접기 + 할 일 먼저 정렬. 데이터: `v_requests_brand`·`v_offers_brand`·샘플·발주를 request_item 기준으로 합친 뷰 하나(`v_progress_brand`, 신규 — 읽기 전용, 원가 없음).

**청구 v2.2**(신규, `/b/[slug]/billing`; `/exports` 흡수) — "청구" / "쇼핑몰용 상품 파일" 버튼 → 4칸 셋: 청구 예정(40) · 납부한 선금(40) · **입금 계좌**(은행·번호·예금주 + "입금 뒤 발주 화면에서 입금 신고") → "발주 n" 표 다섯 열(상품(44px 사진 + 이름 + 날짜) · 수량 · 청구 · 지금(문장) · 내역 링크) — 상품가·수수료·물류·선금 분해는 발주 상세 청구표에서 → "쇼핑몰용 상품 파일 n" 행(이름 · "상품 정보 CSV 2 · 사진 6장" · 내려받기).

**제안 상세 v2.2** — 진행 카드에서 진입. 6칸 큰 사진 + 썸네일 5 / 6칸: 13 메타("새 제안 · 에코퍼 F/W 2번 항목 · 11월 18일까지 유효") · 이름 28 · 한 문장("위아더가 11월 2일 항저우에서 실물을 확인했어요") · 장당 공급가 40(수수료 포함, "50장부터"; dl: 150장부터 · 샘플) · 사실 다섯 줄(`.kvl`: 색상 점·사이즈·소재·세탁·공급) · 버튼 "관심 · 샘플에 담기"(52, ink) + "보류"(52, sec) + "관심 없어요"(링크). 트랙·스펙 표·코드 없음.

**발주 상세 v2.2** — 13 메타("발주 · 11월 4일 · 리오더") · 제목 28 = `{상품명} {수량}장`(외 n은 muted) → **지금 상태 블록**(`.nowblock`) → 일정 3칸("11월 6일") → 옵션 표(옵션 · 주문 · 확보 · 확정) + 부족 한 문장 → "지금까지" 타임라인 | "위아더에게" 메시지. 오른쪽 4칸 "청구 금액" 청구표(항목 이름 사람 말: 상품 35장 · 소싱 서비스 20% · 물류 · 낸 선금 · 청구). 눈썹 대문자·#id·핸드오프 카드·트랙 없음. 샘플·요청 상세도 같은 뼈대.

**B-02 요청 작성** — 단일 칸 760. 머리(제목·한 문장·단계 3) → 항목 n(사진 자리 200px 3:4 왼쪽 + 밑줄 입력) → "+ 항목 추가"(보조) → 요청 정보 → 바닥 바(요약 "항목 1 · 사진 0 · 링크 1" + "요청 올리기" 52px).

## 6. 문구 규칙 (ko.json 전체 적용)

1. 제목 = 정보(상품명·수량·금액). 날짜는 눈썹/메타로.
2. 설명은 0~1문장. 두 문장째는 버튼이나 다음 화면이 말한다.
3. 인사말·화면 설명·UI 지시("~를 참고하세요", "~순서로 모았어요") 금지.
4. 주어 생략. "위아더가 ~하고 있어요" → "~ 중" 또는 "~해요". 위아더는 필요할 때만 명사로.
5. 버튼 = 동사 2~4자. 문장형 버튼·화살표 금지. 결과를 말한다("이메일로 로그인", "입금 신고").
6. 상태명 2~5자 명사. 핸드오프 제목은 "행동 + 대상(+금액)" 20자 이내.
7. 숫자는 글 앞에("₩221,390을 입금해 주세요", "샘플 1점을").
8. 괄호 설명 금지 — 필요하면 도움말 줄(12px muted)로.

전후 표(20개)는 프로토타입 "스타일 가이드" 아래. 구현 시 ko.json 전체를 이 규칙으로 훑는다(약 900키 중 브랜드 노출 문장형 키 ~150개 예상).

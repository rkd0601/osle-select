## v2.3
1. **첫 화면** — 요청이 0건인 브랜드(추천 제안만 있어도)의 홈 = "찾는 상품이 있나요?"(display + 금색 룰) + 두 문장 + "첫 상품 요청하기"(52) + "예시 요청 보기" → 4단계(3칸씩, 금색 번호) → 자주 묻는 것 4(6칸씩). 4단계·FAQ는 `components/domain/service-guide.tsx` 하나를 **설정 › 이용 안내** `/b/[slug]/help`와 같이 쓴다(설정 머리 오른쪽 "이용 안내" 링크, 메뉴는 "설정" 활성). "예시 요청 보기"는 이용 안내의 `#example`(예시 요청 다섯 줄). 문구 `first.*`·`help.*`. 브랜드 B(요청 0건)로 확인.
2. **요청 작성 v2.3** `requests/new` — "항목" → **스타일**. 스타일 카드(surface + line-strong): 머리(스타일 n · 제목 · 삭제) → **사진 올리기 | 또는 | 링크 붙여넣기**(960 미만 위아래) → 한 줄 설명 * → 카테고리 · 예상 수량("아직 몰라요") · 희망 공급가(천 단위 표시) → 색상·사이즈·소재 메모. 열린 스타일은 하나, 나머지는 접힌 한 줄("스타일 2 · … · 링크 1 · 30~100장 / 펼치기"). 링크 최대 5개("+ 링크 추가"), **URL 2개 이상을 붙여넣으면 첫 URL은 지금 스타일, 나머지는 스타일 하나씩 새로**(최대 20). "+ 스타일 추가" 전폭 52 + 안내 한 줄. "요청 전체"(이름 · 언제까지 · 메모, 8칸 안 3·2·3). 오른쪽 4칸 sticky 레일: 담긴 스타일 목록(금색 번호 · 이름 · 사진/링크 수) + "스타일 n개 요청하기" + 한 문장 + 검증 한 줄. 가짜 단계(1·2·3) 삭제. 관리자 대행 요청 화면도 같은 폼.
   - **데이터: 마이그레이션 없음.** 링크 여러 개는 이미 `request_images.source_url` 행으로 저장된다(스키마 `links` 최대 5) — §0-e의 `request_items.reference_url`은 원래 없는 컬럼이라 `reference_urls text[]`를 만들 필요가 없었다. 스타일별 메모는 저장할 컬럼이 없어서 요청 메모 끝에 "[스타일 n] …" 줄로 합친다(`mergeStyleNotes`, 번역·관리자·CN 화면이 이미 요청 메모를 보여 줌). 질문 1.
   - 클라이언트 번들 규칙(zod 금지) 때문에 붙여넣기 분리·검증은 `lib/request-links.ts`(zod 없음)로.
3. **접수 완료** `requests/[id]?submitted=1` — "요청이 접수됐어요" + 금색 룰 + "스타일 n개 · {날짜}까지 제안받기" → 큰 타임라인 3줄(지금 / ~+5일 현장 확인 / ~희망일(없으면 +10일) 제안 도착) → "진행에서 보기"/"스타일 더 요청하기" → 오른쪽 첫 스타일 카드. 브랜드 요청 작성 뒤 이 화면으로 온다.
4. **새 제안 첫 안내** — 진행 화면에 반응 전 제안이 있으면 맨 위 한 줄(`.notice`) "제안이 도착했어요. 마음에 들면 '관심 · 샘플에 담기'를…" + 닫기. 닫으면 다시 안 나온다 — **이 브라우저 localStorage(브랜드별 키)**. 질문 2.
- **추천 묶음(d-15)** — 요청 없이 위아더가 보낸 제안(끝난 것 제외)을 진행 맨 아래 "추천 · 요청하지 않았지만 위아더가 골라 보낸 상품" 묶음으로. 개발 DB엔 추천 제안이 0건이라 화면으론 못 봤다.
- 진행 묶음 머리 "항목 n" → "스타일 n"(d-13).

## 3차 검증
- **T1 샘플 상세** — 피드백 뒤 회수 대기면 `.nowblock` "샘플을 돌려보내 주세요"(기한 · 미회수 상품가 안내) → `.choice` 둘("돌려보낼게요" + 운송장 / "갖고 있을게요 (미회수)" + 상품가) → "회수 신청" 하나. 받음(delivered)이면 `.choice` 관심·보류·거절 + "피드백 보내기". 피드백은 사실 3칸(받은 옵션 · 검품 · 내 피드백 "관심 · 발주서에 담김"). "발주 담기" 삭제. 서버 액션(`giveSampleFeedback`·`setSampleReturn`)은 그대로. 메타 "샘플 · 11월 4일 받음", 오른쪽 "샘플비".
- **T2 요청 상세** — `.nowblock` 문장을 항목별 진행 카드에서 만든다("1번 에코퍼 크롭 카라는 발주 진행 · 2번 롱 코트는 찾는 중"), 썸네일은 카드 사진(요청 사진 또는 제안 상품), 없으면 빗금. 항목 행 상태·버튼도 같은 카드("제안 보기/샘플 보기/발주 보기"). 진행 중인 카드를 끝난 카드보다 먼저 고른다(거절된 제안이 새 제안을 덮지 않게).
- **T3** 항목 행 오른쪽 끝 "취소"(13 muted).
- **T4** 대표 사진 = `sort_order` 1번(동순위 id) — 제안 상세·썸네일·청구·진행·샘플·발주 작성·발주 상세·라인시트 PDF 전부(`lib/images/order.ts` `bySortOrder`). 이전엔 "실拍 우선" 비교가 일관되지 않아 뒷면이 커버로 나왔다.
- **T5** 청구 "쇼핑몰용 상품 파일"은 같은 상품 묶음의 최신 1건만, 나머지는 "이전 파일 n"으로 접기(E2E 선택자 유지).
- **T6** 색상 hex가 없으면 점 없이 이름만(제안 상세 · variant 매트릭스).
- **T7** 홈·진행 카드 이름에서 요청 이름 접두어를 뗀다(`itemName`: 설명이 "X — Y"이고 요청 이름이 X로 시작하면 Y). 개발 DB "2차 점검 — 울 니트 가디건 (오버핏)" → "울 니트 가디건 (오버핏)".
- 진행 카드 대표 사진 = `sort_order` 1번(동순위는 id) — T4와 같은 규칙.

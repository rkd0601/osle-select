- 대상: **dev Supabase 프로젝트만.** 운영 DB에는 이 데이터가 없다.
- 실행: [`scripts/cleanup-autocheck-2026-11-10.sql`](../scripts/cleanup-autocheck-2026-11-10.sql)
- 소요: 1분 이내. SQL 한 번 실행하고, 원하면 Storage 파일을 지운다.

## 실행 방법

1. Supabase 대시보드에서 **dev 프로젝트**를 열고 **SQL Editor**로 간다.
2. `scripts/cleanup-autocheck-2026-11-10.sql` 내용을 전부 붙여 넣고 **Run**을 누른다.
3. 결과 표 8줄이 **모두 0**이면 끝이다.

안전장치:
- 확인 블록이 먼저 돈다. 요청 제목, 상품 코드·이름이 점검 데이터와 다르면 아무것도 지우지 않고 오류를 낸다.
- 샘플 요청서나 발주서에 점검 외 상품이 섞여 있어도 멈춘다.
- 전체가 한 트랜잭션이다. 중간에 오류가 나면 전부 되돌아간다.

## 지우지 않는 것

- **감사 로그(audit_logs, 약 115건):** 감사 기록은 남긴다. 대상 행이 없어져도 화면에는 영향이 없다.
- **숨김 처리된 "E2E 测试商品 …" 상품 6개와 E2E 브랜드:** 따로 정리한다. `CLEANUP_E2E=1 node --env-file=.env.local scripts/cleanup-e2e.ts --apply`

## 되돌릴 수 없어서 알려 두는 것

점검 첫 회에 다음 두 가지가 바뀌었다. 테스트에는 지장이 없다.

- **오슬 계정 알림:** 점검 전에 오던 오슬 계정 알림이 '읽음'으로 바뀌었다.
- **오슬 기본 배송지 메모:** 메모 칸이 빈 값이 되었다. 이 버그는 이미 고쳤다(0e586d6). 원래 메모가 필요하면 오슬 브랜드 설정 → 기본 배송지에서 다시 입력한다.
